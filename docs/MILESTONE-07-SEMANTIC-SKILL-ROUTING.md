# 里程碑 07：Skills 语义路由与供应链校验

## 本阶段解决了什么

里程碑 06 已经能按生成或修复阶段加载 Skill，但阶段内的技能集合仍然固定。本阶段将路由升级为两层：

```text
任务上下文
  -> 确定性阶段过滤（GENERATION / REPAIR）
  -> 保留阶段必选技能
  -> 本地 BGE 编码任务与候选技能描述
  -> 计算余弦相似度
  -> threshold + Top-N 选择可选技能
  -> 校验 SHA-256 与工具声明
  -> 加载正文并记录路由分数
```

确定性阶段保证修复时不会加载代码生成技能；语义层让导出、安全等专项能力只在相关需求中出现。

## 语义路由

`StandardCodingSkillProvider` 将需求、需求卡片、已审批技术方案以及必要的构建证据组成路由上下文，最多使用 6,000 字符。基础生成或失败修复技能由工作流阶段强制选择；可选技能使用项目已有的本地 BGE 模型计算相似度，默认阈值为 0.42，最多加载两个，避免上下文无限膨胀。

本轮新增 `export-reliability` Skill，封装数据范围、流式分页、异步任务、格式白名单、失败恢复和审计约束。真实本地 BGE 冒烟中，同一导出需求得到：

- `java-code-generation`：阶段必选；
- `export-reliability`：0.698；
- `security-review`：0.631；
- `test-failure-repair`：因阶段不符未进入候选集。

路由分数进入 `SKILLS_ACTIVATED` 事件，前端 Checkpoint 时间线可以直接展示选择依据。

## Skill 供应链防护

项目新增 `agent-skills/manifest.sha256`。应用启动时会：

1. 校验 Skill 命名、描述、阶段和正文大小；
2. 检查 `allowed-tools` 是否属于宿主明确允许的声明集合；
3. 将 UTF-8 文本换行规范化为 LF 后，对完整 `SKILL.md` 计算 SHA-256，避免 Windows 与 Linux 换行差异误报；
4. 与评审后提交的可信清单逐项比对；
5. 检查技能目录与清单没有缺项或多余条目。

任一检查失败都会 fail-fast。前端技能卡展示阶段、声明工具、文件大小和摘要前缀，`GET /api/skills` 仍不返回完整正文。

清单能发现运行时篡改和未经评审的内容变化，但它不是数字签名。能同时修改应用包与清单的攻击者仍然可以重新计算摘要；生产环境还需要签名发布、制品仓库校验和依赖来源审计。

## 本轮验证

- 4 个 `SKILL.md` 使用 UTF-8 模式通过 `quick_validate.py`。
- 验证导出与权限需求能够选中两个专项 Skill，并保存相似度分数。
- 验证 REPAIR 阶段强制保留修复技能且不加载生成、导出技能。
- 验证 Skill 摘要与清单不一致时拒绝启动。
- 验证 Skill 声明未知宿主工具时拒绝启动。
- 累计 76 个自动化测试全部通过。
- 真实本地 BGE 冒烟通过；HTTP 202、Checkpoint 和 Docker 不可用安全停止行为保持正常。

## 本阶段简历可写版本

- 设计 Agent Skills 两级路由机制，先通过工作流阶段约束候选范围，再使用本地 BGE 对任务上下文与技能描述进行向量匹配，以相似度阈值和 Top-N 预算动态加载专项能力；路由分数写入任务 Checkpoint，支持前端审计。
- 新增导出可靠性 Skill，沉淀数据范围、流式处理、异步任务、格式白名单和审计策略；真实导出需求下语义路由相似度达到 0.698，并同时激活安全复核能力。
- 实现 Skill 供应链校验：启动时检查阶段和宿主工具白名单，对技能内容计算 SHA-256 并与可信清单比对；摘要篡改、未知能力声明或清单缺项时 fail-fast。
- 累计完成 76 个自动化测试，覆盖语义路由、阶段隔离、摘要校验、跨平台换行、越权工具拒绝、渐进式正文加载及异步编码任务回归。

## 当前真实边界

- 当前使用技能描述向量进行检索，尚未训练专用路由器或构建大规模 Skill 路由评测集。
- 阈值 0.42 来自当前技能和冒烟案例，后续需要基于更多真实任务统计 Precision、Recall 和误加载率。
- SHA-256 清单提供完整性验证，不等同于开发者数字签名或远程供应链认证。
- 技能仍随应用 classpath 发布，尚未实现多租户、远程注册表、版本解析和热更新。
