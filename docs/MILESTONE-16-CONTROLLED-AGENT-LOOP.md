# 阶段 16：受控 Agent Loop

## 要解决的问题

项目此前已经存在 `生成 -> 测试 -> 修复 -> 再测试` 的循环，但循环主要表现为业务代码中的 `while(true)`。它能够工作，却还不能完整回答生产 Agent 必须回答的问题：

- Agent 当前观察到了什么？
- 为什么选择这个动作？
- 动作之后是否真的取得进展？
- 为什么继续，又为什么停止？

本阶段将编码流程显式建模为受控的 Observe–Decide–Act–Validate 循环，并把轨迹放入可恢复 Checkpoint。

## 状态模型

`AgentLoopState` 保存：

- 最大步骤数与已消耗步骤数；
- 连续无进展次数；
- 明确的停止代码和停止原因；
- 完整的 `AgentLoopStep` 列表。

每个步骤记录：

- `observation`：执行前看到的任务状态；
- `action`：生成补丁、运行沙箱测试、修复补丁或请求人工审批；
- `rationale`：为什么选择该动作；
- `outcome`：真实执行或验证结果；
- `progressMade`：是否产生新信息或更接近目标；
- `fingerprint`：用于检测重复行动的 SHA-256，不存放额外源码和完整日志；
- `occurredAt`：发生时间。

## 执行流程

```text
观察：技术方案已审批、工作区为空
决策：GENERATE_PATCH
行动：模型或 Mock 生成受限 Java 文件
验证：Schema + SandboxPolicy
  -> 记录步骤和方案指纹

观察：补丁尚未经过真实测试
决策：RUN_SANDBOX_TEST
行动：无网络 Docker 内离线 Maven 测试
验证：exit code、测试结果和日志摘要
  -> 通过：REQUEST_HUMAN_APPROVAL，暂停循环
  -> 失败且有预算：REPAIR_PATCH
  -> 重复失败/无进展/预算耗尽：FAILED，明确停止代码
```

模型负责生成和依据错误证据修复代码，Java Harness 负责流程选择、预算、指纹比较、状态持久化和停止条件。模型不能自行增加步骤或跳过人工审批。

## 有界自治

默认预算为：

- 最多 6 个文件；
- 最多 100KB 生成内容；
- 最多 3 次 Docker 构建；
- 最多 180 秒累计沙箱时间；
- 最多 8 个 Agent 动作。

八步可以覆盖最坏的正常路径：生成、测试、修复、测试、修复、测试、请求审批，并保留一个安全余量。

## 无进展检测

系统对按路径排序后的文件内容计算稳定方案指纹，并对“方案指纹 + 测试是否通过 + 退出码 + 日志摘要”计算构建行动指纹。

- 修复结果与上一版文件完全一致：立即停止，不再执行相同测试；
- 候选方案循环回历史版本并产生相同失败证据：判定重复循环并停止；
- 连续动作没有产生新信息或新候选：触发 `NO_PROGRESS`；
- 只保存 SHA-256 和简短结果，避免在 Loop 轨迹中重复保存敏感源码或日志。

## 停止语义

`AgentLoopStopCode` 区分：

- `WAITING_HUMAN_APPROVAL`：测试通过，需要人检查 Diff；
- `GOAL_REACHED`：人工批准后产物已进入独立输出目录；
- `STEP_BUDGET_EXHAUSTED`：动作数达到上限；
- `EXECUTION_BUDGET_EXHAUSTED`：构建次数或执行时长达到上限；
- `NO_PROGRESS`：重复补丁或重复失败证据；
- `FAILURE`：基础设施、安全策略或未处理异常。

停止原因与步骤轨迹随 `CodingTask` 文件 Checkpoint 持久化。历史阶段 16 之前没有 Loop 字段的 JSON 会初始化为空状态，不影响读取。

## 前端体验

代码任务区域新增“受控 Agent Loop”视图：

- 展示步骤消耗 `已用 / 最大`；
- 每步展示观察、决策、验证结果和是否有进展；
- 展示等待审批、目标完成、预算耗尽、无进展或异常等停止原因；
- 保留原有 Checkpoint 时间线、构建记录、Diff 和人工审批。

## 验证

- 正常生成并一次测试通过：进入人工审批；
- 首次失败、补丁发生变化、第二次测试通过：保存 5 个可解释步骤；
- 修复返回相同补丁：只执行一次构建并以 `NO_PROGRESS` 停止；
- 修复持续产生不同候选但测试失败：3 次构建后以执行预算停止；
- 步骤预算耗尽：拒绝继续动作；
- Loop 状态和指纹可随文件 Checkpoint 重载；
- API 返回步骤预算和 Loop 状态，前端完成可视化；
- 全项目 118 个自动化测试通过。

## 当前边界

- 下一步动作由确定性 Harness 根据测试状态选择，不是开放式模型规划；这保证安全和可测试性，也意味着动作集合目前仅覆盖编码链路；
- 当前没有接入 OpenTelemetry Trace 或跨服务事件总线；
- 文件 Checkpoint 只支持单实例恢复，没有多实例任务租约；
- Docker 成功链路仍依赖运行机器具有可用 Docker 与离线 Maven 依赖；
- 输出仍是独立演示工程，不会创建真实 Git 分支或 Pull Request。
