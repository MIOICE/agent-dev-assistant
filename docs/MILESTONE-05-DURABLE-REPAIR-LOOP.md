# 里程碑 05：后台执行、Checkpoint 与有界自动修复

## 本阶段解决了什么

此前代码任务在 HTTP 请求线程内同步完成，而且任务状态只存在内存中：执行时间较长时容易请求超时，服务重启也会丢失进度；测试失败只能停止，无法利用失败证据修正代码。

本阶段将它升级为可恢复的后台 Coding Agent：

```text
POST 提交任务
  -> 持久化 QUEUED Checkpoint
  -> 返回 HTTP 202
  -> 有界线程池后台执行
  -> GENERATING：生成并校验补丁
  -> VERIFYING：Docker 沙箱测试
  -> 失败：REPAIRING，模型根据失败证据修复
  -> 再次执行策略校验与沙箱测试
  -> 最多 3 次构建 / 2 轮修复
  -> 成功：WAITING_APPROVAL
  -> 预算耗尽或基础设施异常：FAILED
```

## 为什么这比普通重试更像 Agent

普通重试只是用相同输入重复调用。这里的下一步由上一步环境反馈决定：测试输出成为新的观察，修复器结合原需求、已审批方案、上一版文件和错误证据生成新动作，再由确定性策略与执行环境验证结果。这形成了受控的 `观察 -> 修复 -> 执行 -> 再观察` Agent Loop。

循环不是无限的。默认自治预算为：

- 最多 6 个 Java 文件。
- 最多 100KB 当前生成内容。
- 最多 3 次 Docker 构建。
- 最多 180 秒累计沙箱执行时间。
- 单次 Docker 构建最多 60 秒。
- 因此最多进行 2 轮模型修复。

## 修复安全边界

- 只有 Docker 正常返回编译或测试失败才调用修复模型。
- Docker 不可用、路径异常、依赖仓库缺失和策略拒绝会直接停止。
- 构建日志被视为不可信数据，放入明确分隔符并截断到 6000 字符。
- 修复结果必须保持上一版文件路径集合完全一致。
- 不允许删除测试、放宽断言、修改 `pom.xml` 或新增依赖。
- 每一版仍要经过 JSON Schema、目录、扩展名、危险 API、文件数和字节数校验。
- 最终发布前继续使用 SHA-256 防止验证后文件被替换。

## Checkpoint 与恢复语义

`CodingTaskRepository` 保存任务的完整不可变快照，包括：

- 当前阶段和工作区 ID。
- 创建任务时固化的已审批工作流输入快照。
- 自治预算及已消耗的构建次数、沙箱耗时。
- 修复轮数、当前补丁和 SHA-256。
- 每一次构建结果与完整事件时间线。
- 失败原因或批准产物路径。

默认 `FileCodingTaskRepository` 将每个任务保存为独立 JSON。写入时先生成同目录临时文件，再使用原子替换发布快照，避免进程中断留下半份 JSON。代码任务同时固化已审批的工作流输入，因此即使原工作流使用内存仓库，恢复过程也不会丢失需求与技术方案。应用启动后扫描 `QUEUED`、`GENERATING`、`VERIFYING`、`REPAIRING` 状态并重新调度。

构建次数在启动 Docker 前就写入 Checkpoint。即使进程在测试期间崩溃，重启后也不会返还这次预算。恢复使用新的任务工作区，不覆盖执行可能不完整的旧目录。当前属于单实例、至少一次调度；由于人工批准前没有真实业务副作用，重复生成是安全的。

## 异步执行

创建接口返回 `202 Accepted`，不等待模型与 Docker。后台使用固定大小线程池和有界队列，防止请求量突然增加时无限创建线程。前端每 1.2 秒轮询任务快照，并展示：

- QUEUED、GENERATING、VERIFYING、REPAIRING 等阶段。
- 文件、字节、构建次数、修复轮数和沙箱时间预算。
- Checkpoint 事件时间线。
- 每次构建的退出码、耗时和最终补丁 Diff。

## 本轮验证

- 累计 68 个自动化测试全部通过。
- 新增验证：第一次构建失败、修复后第二次成功。
- 新增验证：连续失败时第三次构建后预算耗尽并安全停止。
- 新增验证：HTTP 任务提交和后台执行分离。
- 新增验证：中断任务继承已消耗预算并恢复执行。
- 新增验证：文件 Checkpoint 在模拟进程重启后能够重新读取。
- 前端 JavaScript 独立语法检查通过。

## 本阶段简历可写版本

- 设计异步 Coding Agent，将代码生成和容器测试从 HTTP 请求线程解耦，通过固定线程池、有界队列和任务状态轮询实现长任务后台执行。
- 实现基于构建反馈的 Generate–Test–Repair 循环，模型根据编译/测试错误生成受限修订版；每轮重新执行结构化与安全策略校验，并以最多 3 次构建、2 轮修复及 180 秒沙箱时间限制自治范围。
- 抽象 `CodingTaskRepository` 并实现原子 JSON Checkpoint，持久化任务阶段、补丁、构建历史和预算消耗；应用重启后自动恢复未完成任务，并采用预算预扣与新工作区策略避免崩溃后无限重试。
- 累计完成 68 个自动化测试，覆盖 HTTP 202 异步入队、失败修复、预算耗尽、Checkpoint 重载、重启恢复及二次人工审批。

## 当前真实边界

- Checkpoint 是单机文件存储，不是分布式工作流引擎。
- 固定线程池不是跨实例消息队列；多实例部署还需要任务租约、分布式锁或队列消费者语义。
- 当前电脑仍未提供可用 Docker CLI，因此真实容器成功链路尚未在本机完成；单元测试使用可控 Sandbox Runner 验证状态机，实际运行会在 Docker 不可用时安全停止。
- 修复循环还没有按模型 Token 和费用单独计量，当前限制文件、构建次数和沙箱时间。

这些边界应在面试中主动说明，避免把作品集级实现描述成生产级分布式 Durable Runtime。
