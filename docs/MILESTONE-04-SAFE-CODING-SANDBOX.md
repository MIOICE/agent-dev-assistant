# 里程碑 04：安全代码工作区、自治预算与二次审批

## 本阶段解决了什么

项目从“生成技术方案”继续推进到“生成可审查代码产物”。只有已经完成技术方案人工审批的工作流才能创建代码任务。DeepSeek 模式根据需求卡片和技术方案生成结构化 `CodePatchPlan`；Mock 模式生成可重复验证的订单导出策略与测试。

Agent 不直接修改当前项目，而是：

```text
已审批技术方案
  -> 生成结构化文件计划
  -> 确定性安全策略校验
  -> 写入任务专属工作区
  -> 生成 Unified Diff 与 SHA-256
  -> Docker 隔离容器执行离线 Maven 测试
  -> WAITING_APPROVAL
  -> 人工审查 Diff、测试、预算
  -> 复制到独立批准产物目录
```

## 为什么普通文件夹不叫沙箱

最初设计曾考虑在宿主机用 `ProcessBuilder` 直接运行 Maven，但普通目录隔离无法阻止生成代码读取环境变量、访问网络或读取其他磁盘文件，因此该方案被放弃。

当前执行边界是 Docker 容器：

- `--network none`：生成代码没有网络。
- `--read-only`：容器根文件系统只读。
- `--cap-drop ALL` 与 `no-new-privileges`：移除额外 Linux 权限。
- 限制 1 CPU、512MB 内存、128 个 PID 和 60 秒运行时间。
- 任务源代码与 Maven 本地仓库只读挂载。
- `target` 使用 128MB tmpfs，限制构建输出空间。
- 固定执行离线 `mvn test`，不允许模型提供命令。
- Docker 不可用时直接失败，不降级到宿主机执行。

这仍然是作品集级执行环境，不等同于云厂商的微虚拟机沙箱。生产环境还应加入 seccomp/AppArmor、独立容器节点、镜像签名、磁盘配额和集中审计。

## 自治预算

每个任务默认最多：

- 6 个 Java 文件。
- 100KB 生成内容。
- 1 次构建执行。
- 60 秒执行时间。

路径只允许位于 `src/main/java/demo/generated/` 和 `src/test/java/demo/generated/`。当前阶段只允许新增 `.java` 文件，同时拦截进程、网络、文件系统、反射、环境变量和 JVM 退出等能力。

自治预算的意义不是让 Agent 更聪明，而是限制失败半径：即使模型产生错误规划，它能消耗的文件、时间、进程和资源仍有确定上限。

## Human-in-the-loop 与 TOCTOU

技术方案审批和代码产物审批是两个不同检查点：前者确认“怎么做”，后者确认“实际改了什么”。沙箱测试通过后保存每个文件的 SHA-256；发布前重新计算并对比，避免测试后的文件被替换，这属于对验证与使用之间时间差问题的基本防护。

## 本轮验证

- 63 个项目自动化测试全部通过。
- 覆盖路径穿越、危险宿主能力、文件数预算、测试失败禁止发布、技术方案未审批禁止编码、SHA-256 与人工批准产物链路。
- 前端 JavaScript 独立语法检查通过。
- 当前电脑未检测到 Docker CLI，因此没有声称完成真实容器成功冒烟；运行代码会安全地返回失败，不会回退到宿主执行。安装并启动 Docker Desktop、准备指定 Maven 镜像后即可从页面完成真实容器验证。

## 本轮简历可写版本

- 基于已审批技术方案构建安全编码任务，将模型输出约束为结构化 Java 文件计划，生成 Unified Diff 与 SHA-256，并通过文件目录、扩展名、危险能力及文件数/字节数自治预算进行确定性校验。
- 设计无网络 Docker 代码验证环境，采用只读根文件系统、只读源码和依赖挂载、Linux Capability 清理、`no-new-privileges`、CPU/内存/PID/时间及临时磁盘限制，固定离线执行 Maven 测试；Docker 不可用时禁止降级到宿主执行。
- 建立“技术方案审批—沙箱测试—代码审批”双重 Human-in-the-loop，测试失败禁止发布，并在批准前使用 SHA-256 校验产物完整性，最终仅输出到独立批准目录而不直接修改真实仓库。
- 累计完成 63 个自动化测试，覆盖 Agent 工作流、RAG、MCP 工具治理、路径穿越、自治预算和安全发布状态机。
