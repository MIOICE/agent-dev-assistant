# 里程碑 02：Agent Trace 与运行评测

## 为什么需要

普通后端接口只关心成功或失败，但 Agent 会经过需求分析、知识检索、方案生成和人工决策等多个节点。只看最终结果，很难判断是模型慢、检索没有命中，还是工作流规则导致反复澄清。

本轮实现了两层可观测能力：

- 单次 Trace：每个核心节点生成 `AgentTraceSpan`，记录统一 `traceId`、独立 `spanId`、状态、起止时间、耗时和统计属性。
- 聚合 Eval：从真实工作流快照、事件和 Span 计算首轮就绪率、平均澄清轮数、推荐值采纳率、完成率、失败率和平均节点耗时。

失败 Span 只记录异常类型，不保存密钥、完整 Prompt 或敏感业务数据。Trace 随 `WorkflowState` 一起保存，因此使用 MySQL 模式时重启后仍可查询。

## 接口

- `GET /api/workflows/{workflowId}/trace`：返回单次工作流全部 Span 与总耗时。
- `GET /api/workflows/metrics`：返回当前仓库内工作流聚合指标。

## 本轮验证

- `mvn clean test`：51 个自动化测试全部通过。
- Mock 端到端冒烟：完整需求生成 3 个成功 Span；模糊需求采用推荐值后保留原 `workflowId` 并进入 `WAITING_APPROVAL`。
- 聚合指标接口正确统计 2 条样例工作流、平均澄清轮数 0.5、推荐值采纳率 100%。
- 前端 JavaScript 语法检查通过，指标看板和调用轨迹资源加载成功。
