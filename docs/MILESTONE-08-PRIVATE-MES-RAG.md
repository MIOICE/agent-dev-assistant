# 里程碑 08：私有 MES 语料治理与混合 RAG

## 本阶段解决了什么

此前知识库只有 3 份演示规范，能证明 RAG 链路可运行，却不能证明 Agent 能理解真实存量系统。本阶段将经过授权和脱敏的外部 MES Markdown 以只读方式接入，同时把检索从“纯向量 Top-K”升级为可解释的混合检索。

```text
外部 MES 目录（只读）
  -> 路径允许列表 + 文件数量/大小限制 + 禁止符号链接
  -> 跳过目录节点和无关文档
  -> 敏感模式脱敏
  -> 提取模块、分类、文档类型和来源路径
  -> 按 Markdown H1-H4 标题切分，超长章节二次分块
  -> 本地 BGE 向量索引

用户问题
  -> 向量候选 + 全语料关键词候选
  -> 合并、标题/模块/关键词重排
  -> 同来源 Chunk 数量限制
  -> 最终置信度门槛
  -> 返回正文、来源、标题链、向量分和综合分
```

## 语料治理

外部知识库默认关闭，只有设置 `MES_KNOWLEDGE_ENABLED=true` 且提供有效根目录才会加载。允许范围只有：

- `summary` 下的实际业务页面 Markdown；
- `document` 下命名符合规则的需求卡片、需求分析和整体方案。

README、目录树、下划线开头文件、目录节点、超大文件和其他目录全部跳过。扫描不跟随符号链接，加载过程不会修改、复制或提交原文件。入库前会基础替换疑似密钥、IPv4、邮箱、手机号和 Windows 绝对路径；状态接口只展示数量，不暴露本地根路径。

这不是完整的数据防泄漏系统。正则无法识别所有客户名、内部术语和上下文敏感信息，生产环境仍需要文档分级、租户授权、专门 DLP 和持久化审计。

## 标题感知分块

固定长度分块适合纯文本，但业务页面通常包含“字段、Controller、Service、数据表、接口”等章节。`BusinessDocumentChunker` 维护 H1-H4 标题链，将标题路径作为 Chunk 的检索前缀和元数据；仅当章节仍过长时才交给 Token 分块器二次切分。

这样做有三个好处：

1. 标题不会与正文失联；
2. 检索结果可以定位到具体页面章节；
3. 模型获得模块、页面和小节语义，不必读取整篇文档。

## 混合检索与拒答

纯向量检索对同义表达友好，但在页面名、接口名和表名等精确词上可能排序不稳。本阶段并行构建两类候选：

- 本地 BGE 相似度召回；
- 基于页面标题、模块、分类、关键词和二元词覆盖率的全语料词法召回。

两类候选按 Chunk ID 合并，保留原始向量分并计算综合分。精确页面标题即使未进入向量候选也能被补回；同一来源最多返回两个 Chunk，避免长文档占满 Top-K。综合分低于 0.65 时不返回结果，降低“首页颜色”“请假审批”等越界问题的误命中。

## 本轮实测

在本机授权语料上：

- 总文档 240 份：内置 3 份、外部 237 份；
- 生成 3311 个 Chunk；
- 跳过 144 份不满足允许规则或内容规则的 Markdown；
- 2 份文档在入库前触发基础脱敏；
- 典型生产订单页面查询由纯向量候选第 3 位提升为混合排序第 1 位；
- 两个越界问题均被置信度门槛拒绝；
- 12 条评测全部通过，Hit@K 100%、MRR 100%、无关问题拒绝率 100%、Precision@K 55%；
- 84 个自动化测试全部通过。

Precision@K 为 55% 并不代表只有 55% 的回答正确。当前相关性标签按来源文档计算，而 Top-4 可能包含同一来源的两个有效章节，其他补充来源也未必被标为相关。该指标主要用于回归对比，不能替代人工金标集。

外部评测题从本地文档标题和来源 ID 动态产生，只用于语料可检索性冒烟；公共源码不硬编码私有文档内容。后续应在仓库外维护经过业务专家标注的独立评测集。

## 当前真实边界

- 语料只读接入与基础正则脱敏不等于完整 DLP 或多租户权限控制。
- 当前使用 `SimpleVectorStore` 在启动时全量索引，本机冷启动约 36 秒；尚未实现增量索引、持久化向量库和索引版本切换。
- 关键词评分是可解释的工程规则，不是 BM25 或学习排序模型。
- 12 条评测适合当前版本回归，外部标题题不是独立人工金标集。
- 检索只提供证据，最终方案仍受结构化校验、工作流状态机和人工审批约束。
